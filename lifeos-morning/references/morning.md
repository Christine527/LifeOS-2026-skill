# 晨间惯例

## 1. 加载背景

读取：

1. `settings.md`
2. `goals.md`
3. `routines.md`
4. 需要承接昨天时读取最近一篇日报

在内部形成“北极星 → 当前阶段 → 活跃目标 → 今日瓶颈”的判断，不复述整份文件。

## 2. 读取今日日程

日历 已启用时：

- 使用 `settings.md` 的时区
- 以本地 00:00 到次日 00:00 的 RFC3339 范围读取事件
- 保留日历中的真实承诺、休息和移动时间

没有 日历 时，使用用户给出的任务清单；不要假装已经读取外部数据。

## 3. 判断今日重点

先检查：

- 是否过载或没有留白
- 是否存在真实截止时间
- 哪个瓶颈最阻碍活跃目标
- 哪项行动能留下发布、交付、验证或可复用资产
- 哪项行动具有复利效应，能沉淀内容、能力、产品、关系、健康、数据、流程、模板或系统资产
- 日常固定项是否有可执行时间窗

选择不超过 3 个真正影响核心目标的杠杠任务。这个数量限制作用于当天行动，不是把用户的人生目标缩减成 3 个。

优先级依次考虑：

1. 不可推迟的真实承诺与截止时间
2. 当前核心目标的关键瓶颈
3. 能产生发布、交付、销售或验证的行动
4. 能让未来行动更容易、更快或价值更高的复利行动

不要为了照顾全部目标而平均分配时间，也不要为了追求复利忽略健康恢复和生活责任。

## 4. 输出今日作战地图

```markdown
🌅 YYYY-MM-DD · 晨间惯例

【今日判断】
用 2～3 句话说明重点、最大风险和关键取舍。

【今日作战地图】
🔴 杠杠任务
1. <行动> → <对应目标> → <最小证据>
2. <行动> → <对应目标> → <最小证据>
3. <行动> → <对应目标> → <最小证据>

🟡 可选挑战
- <只有用户提前指定时才列入>

🟢 日常固定项
- [ ] <从 routines.md 读取>

【一个微行动】
<状态较差时也能开始的最小动作>

【XP 视野】
预计完成这些行动可获得约 <数值> XP。
距离下一等级还差 <数值> XP。
```

如果某一栏没有内容，省略而不是编造。

## 5. 日历 写入

用户要求安排日程时：

- 杠杠任务优先使用 1～2 小时专注块
- 每天最多 3 个
- 固定项放入用户可执行的时间窗
- 保留休息和缓冲
- 创建后回读并简短确认

只给建议而未要求写入时，不修改 日历。

## 6. XP 视野

晨间只做预估，不提前结算。预估时：

- 固定项按实际配置计算
- 同一目标的多项行动只按一条目标进度估算
- 挑战 XP 仅在用户明确指定后计入
- 标注“预计”，不要把计划写成已经获得

## 异常处理

- 日历 不可用：说明连接状态，继续使用本地任务清单
- 日程为空：自然询问是否需要安排今天
- 目标文件缺失：保留当前请求，进入 `$lifeos-onboarding` 创建最小版本后继续
- 用户状态疲惫：把杠杠任务缩到 1 个，并保留恢复时间

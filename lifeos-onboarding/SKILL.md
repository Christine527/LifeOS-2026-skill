# LifeOS 首次配置

通过七个可跳过的问题，把不携带私人数据的公开版补成当前用户自己的 LifeOS。

## 开始前

1. 完整读取 [references/setup.md](references/setup.md)。
2. 完整读取 [references/onboarding.md](references/onboarding.md)。
3. 读取当前对话，保留用户已经提供的信息和进入配置前的原始请求。
4. 已有运行目录时检查 `settings.md`，从第一个未完成的 `Question N/7` 继续。
5. 已完成初始化而用户未要求重新配置时，不重复七问。

## 七问原则

- 每次只发送当前一个问题。
- 第一行严格使用 `Question N/7`。
- 问题本身要简短、直接，不添加多余的介绍或说明文字。
- 用户跳过时记录到 `pending_fields`，不阻止系统启用。
- 已经在当前对话或现有配置中确认的信息不重复询问。
- 只有路径冲突、写入安全或连接对象有歧义时才补问同一编号。
- 日常晨间、晚间和目标对话不得沿用问题编号。
- 目标进度总览的预览年龄、目标年龄、习惯和目标都是演示数据；必须通过当前用户的回答确认，不能直接写入运行目录。

## 保存与恢复

每完成一问：

1. 只保存用户已经确认的内容。
2. 更新 `onboarding_step`。
3. 修改已有文件前先比较并创建备份。
4. 不覆盖同名数据文件。
5. 中断时告诉用户下次从哪个问题继续。

完成 `Question 7/7` 后：

- 展示去敏后的配置摘要。
- 经用户确认、跳过或接受默认值后写入 `onboarding_complete: true`。
- 有待补内容时写入 `profile_status: partial`，以后只在真实使用需要时自然补一项。
- 如果此前已经展示新手教程，写入 `tutorial_seen: true`。
- 初始化 `xp.md`、`projects/` 与 `daily-reviews/`。
- 把人生时间线和习惯等未确认字段写入 `pending_fields`；以后在首次生成目标进度总览时自然补问，不阻止启用。
- 回到用户进入配置前的原始请求。

## 安全边界

- 不询问密码、Token、Cookie、验证码、精确账号标识或不必要的敏感信息。
- 不要求用户一次性讲完人生、资产、健康和关系。
- 不用作者示例替用户完成配置。
- 运行数据目录必须与 技能 目录分离。
- 日历未连接时写 `calendar_status: pending`，不能声称已同步。

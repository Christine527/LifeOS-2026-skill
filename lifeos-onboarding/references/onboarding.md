# 首次个性化引导

公开版不携带任何人的目标、习惯、作息、日历 分类或运行数据。第一次使用时，必须用固定七问把空白位置补成当前用户自己的 LifeOS。

## 启动条件

满足任一条件就启动：

- 找不到运行目录
- 找不到 `settings.md`
- `onboarding_complete` 不是 `true`
- 用户要求"重新初始化 / 重新配置 LifeOS"

如果用户原本要求晨间或晚间惯例，先完成初始化，再自动回到原请求。

## 强制进度格式

首次引导固定为七问。每条向用户提问的消息都必须遵守：

1. 第一行先写且只写 `Question N/7`，其中 N 是当前问题编号。
2. 问题本身要简短、直接，不添加多余的介绍或说明文字。
3. 每次只发送当前这一问，不提前展示后续问题。
4. 用户没有补齐信息时，记录到 `pending_fields` 并进入下一问；只有路径冲突、写入安全或连接对象存在歧义时才用同一个 `Question N/7` 补问。
5. 用户回答"跳过 / 未记录 / 使用默认值"也视为已回应，然后进入下一问。
6. 该格式只用于首次初始化；正常晨间、晚间和目标对话不得继续使用 Question 编号。

不要把 `Question N/7` 翻译成"第几题"，也不要改成 `Q1`、`Step 1` 或其他形式。

## 状态保存

每完成一问：

1. 把已确认内容写入对应运行文件。
2. 把 `settings.md` 的 `onboarding_step` 更新为下一个 `question_N`。
3. 把跳过或未记录的内容加入 `pending_fields`。
4. 不覆盖同名文件；已有文件先比较、备份再修改。
5. 用户中断时明确告诉他下次会从哪个 `Question N/7` 继续。

中断后从第一个未完成问题继续，不重复已经确认的问题。处理完 `Question 7/7` 后即可设置 `onboarding_complete: true`；存在待补字段时写入 `profile_status: partial`。

## Question 1/7：认识 LifeOS 与生活时间边界

首次发送必须使用下面的格式：

> Question 1/7
> 你通常几点起床，几点睡觉？（我需要避开哪些时间安排我们的任务？）

记录到 `settings.md` 和 `goals.md`：

- `wake_time`
- `sleep_time`
- `protected_time_blocks`
- IANA 时区
- 固定承诺与时间限制

能可靠读取系统时区时，可以把检测结果放在问题末尾请用户确认。用户跳过起床、睡觉、不可排任务时间或时区时，写入 `pending_fields`，继续下一问。完成后写入 `onboarding_step: question_2`。

## Question 2/7：北极星、现状与当前主线

消息第一行必须是：

> Question 2/7
> 描述一下你的理想生活？如果可以，请列出最少5个你的目标（事业、收入、健康、关系、运动等等，不封顶）
> 为【目标进度总览】的人生时间线，你愿意提供出生日期（或当前年龄）以及希望显示的目标年龄吗？不想提供可以回复“未记录”。

整理到 `goals.md`：

- 北极星
- 当前状态
- 当前阶段主线
- 会影响决策的角色或长期项目
- 当前资源与限制
- 出生日期或当前年龄（只记录用户选择提供的一种）
- 人生时间线目标年龄
- `life_timeline_status`（`confirmed` / `pending`）

年龄与目标年龄不使用预览中的 `23 / 80` 或任何默认值；缺少内容写"未记录 / 待确认"并加入 `pending_fields`。完成后写入 `onboarding_step: question_3`。

## Question 3/7：活跃目标与完成证据

消息第一行必须是：

> Question 3/7
> 现在选出最想推进的 1～3 个目标。请同步给我：它目前的完成度、下一个关键节点、以及眼前最大的卡点。

每个活跃目标整理为：

- 当前状态
- 理想状态
- 下一里程碑
- 成功证据
- 当前瓶颈

不得为了凑满 3 个目标而自行添加。完成后写入 `onboarding_step: question_4`。

## Question 4/7：日常惯例与练习

消息第一行必须是：

> Question 4/7
> 习惯的引导：日常生活中，有哪些你想保持的习惯（固定项）？
> 举例：饭后吃鱼油、每隔天一次健身房、每天发一条twitter等等
> 它们可以是运动、学习、饮食、整理、表达或任何对你有意义的事情。

规则：

- 不把 技能 示例写成用户习惯。
- 不继承目标进度总览预览或上一位用户的习惯；只有用户原话才是当前习惯清单。
- 不强迫用户凑数量。
- 为每项保留用户自己的原始命名。
- 练习记录关闭时，日报省略该区块。

写入 `routines.md`，然后更新 `onboarding_step: question_5`。

## Question 5/7：iPhone 日历

消息第一行必须是：

> Question 5/7
> LifeOS 完整模式需要联动 iPhone 日历，你的codex是否已经安装google calendar 插件？
如果没有，请找我帮忙，直到我们确认，你的手机端、PC端都能打开一个同步的google日历。

执行规则：

- 不索取密码、Token、Cookie、验证码或账号凭据。
- 日历和外部账号连接由用户自己完成。
- 已连接时先只读检查，再确认日历 ID。
- 尚未连接时写入 `calendar_status: pending`，只输出拟定日程，不声称已同步。
- 未配置颜色时保留事件原色。

记录到 `settings.md`：`calendar_status`、`calendar_id`（已确认时）。
完成后写入 `onboarding_step: question_6`。

## Question 6/7：日报的位置

消息第一行必须是：

> Question 6/7
> 每天晚上的日报，是否需要帮助你同步到你的 Obsidian 仓库，如果是，请提示我你的obs仓库的名字？如果拒绝，我会在本地保存。如果同意，我会在你确认后同步。

执行规则：

- 选择 Obsidian 时只确认已注册仓库和相对归档目录，不索取仓库凭据。
- 选择本地保存时，日报写入运行目录下的 `daily-reviews/`。
- 用户跳过时默认使用本地保存，写入 `pending_fields`。

记录到 `settings.md`：`daily_report_destination`（`local` / `obsidian`）、`obsidian_vault`（选择 Obsidian 时）、`obsidian_archive_dir`（选择 Obsidian 时）。
完成后写入 `onboarding_step: question_7`。

## Question 7/7：确认启用

消息第一行必须是：

> Question 7/7
> 【目标进度总览】中会统计你的 XP（经验值）、活跃目标、完成证据、关键突破、明确指定的挑战等。
> 关于下列XP的分值，你是否同意？
>
> > 日常固定项与晚间惯例每项 +10
> > 同一目标普通推进 +20
> > 明显成果 +30
> > 关键突破 +40～50
> > 明确指定的挑战 +5

在同一条消息中完成两件事：

1. 询问 XP 分值是否沿用上面的默认值，如需修改直接指出。
2. 展示目前七问汇总，并让用户确认启用或直接修改。

使用以下结构展示摘要：

```markdown
【LifeOS 初始化摘要】
- 作息与不可排任务时间：<内容>
- 时区与固定约束：<内容>
- 北极星与当前主线：<内容>
- 活跃目标：<1～3 个>
- 人生时间线：<出生日期或当前年龄；目标年龄；未记录时明确标记>
- 日常固定项：<内容>
- 晚间惯例：<内容>
- 运行目录：<~/.lifeos/ 或自定义>
- 日历：<开启 / 关闭；不显示账号标识>
- 日报位置：<本地 / Obsidian>
- XP 分值：<默认 / 已修改>
- 未记录项：<内容>

如果这些配置可以启用，回复"确认启用"；需要修改时直接指出项目和值；想以后再补可以回复"使用默认值"或"跳过"。
```

用户回复"确认启用""使用默认值"或"跳过"后：

1. 写入 XP 偏好。
2. 写入 `onboarding_complete: true`。
3. 写入 `onboarding_step: complete`。
4. 有待补字段时写入 `profile_status: partial` 和 `pending_fields`；全部补齐时写入 `profile_status: complete`。
5. 初始化 `xp.md`、`projects/` 与 `daily-reviews/`。
6. 明确说明个人数据保存在运行目录，不在 技能 仓库。
7. **向用户说明 LifeOS 使用方式**（使用以下模板）：

```
✅ 配置完成！LifeOS 已就绪。

LifeOS 是一个**每天使用**的系统，日常流程：

🌅 **早上（晨间规划）**
告诉我今天想推进什么，我会：
- 自动查看你当天的 Google 日历
- 根据你的目标和时间红线，选出 1-3 个最重要的任务
- 自动创建或重命名日历事件
- 你确认后安排进日历

🌙 **晚上（晚间复盘）**
告诉我今天做了什么，我会：
- 对照你的日历事件，对任务进行重命名，在开头标记 🎉 代表完成 / ❌ 代表未完成
- 生成当天日报，记录行动、结果、卡点和洞察
- 结算 XP，更新【目标进度总览】

**随时**
- 查看【目标进度总览】：追踪人生时间线、活跃目标进度、习惯打卡

现在可以直接告诉我：
1.查看今日表现
2.查看我的目标进度总览
3.其他：_
```

8. 回到用户最初请求的晨间或晚间流程。

用户在本问修改配置时，直接更新并完成启用；只有修改内容存在歧义时，继续使用 `Question 7/7` 补问，不得创建第八个问题编号。

## 跳过后的运行

七问都可以跳过，LifeOS 使用安全默认值进入部分配置状态：

- 运行目录：默认 `~/.lifeos/`
- 时区：能可靠检测时使用系统时区；否则写入 `pending_fields`，在首次日历操作前补充
- 目标：保持"待确认"，不虚构核心目标；实际安排时只追问当前需要的一项
- 人生时间线：出生日期或当前年龄、目标年龄均保持"待确认"，不得套用预览数字
- 日常惯例：保持空列表，不展示虚假打卡项；用户提到稳定习惯时自然收录
- 日历：写入 `calendar_status: pending`，连接完成前只输出拟定日程
- 日报位置：默认本地保存
- XP：使用默认值，用户后续可以修改

`onboarding_complete: true` 只表示七问已经走完，不表示个人资料完整。`profile_status: partial` 与 `pending_fields` 用于记录仍待补充的内容。

使用中遇到待补字段时：

1. 只询问会改变当前安排、结算或归档的一项。
2. 提醒"这项之前选择了跳过，现在可以补，也可以继续跳过"。
3. 用户回答后更新对应文件，并从 `pending_fields` 移除。
4. 全部待补字段清空时，将 `profile_status` 改为 `complete`。

## 禁止行为

- 不省略 `Question N/7` 进度标识。
- 不在同一条消息中发送两个不同编号的问题。
- 不要求一次性回答全部七问。
- 不把 Question 编号带入日常晨间、晚间或普通目标对话。
- 不询问密码、Token、Cookie、验证码或账号凭据。
- 不把公开版作者的示例、目标或习惯推荐给新用户。
- 不擅自从 日历、文件名或历史聊天推断敏感目标。
- 不因用户拒绝填写收入、健康或关系信息而降低服务质量。
- 不在对话中打印完整个人档案；只展示当前需要确认的摘要。

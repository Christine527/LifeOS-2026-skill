# LifeOS 项目规格

为复杂项目建立一张可验证的完成说明。普通习惯、简单提醒和一次性小任务不建项目文件。

完整读取 [references/project.md](references/project.md)。

## 建立项目

1. 保留用户原始目标，不擅自改写成更大的项目。
2. 记录当前状态与理想结果。
3. 写清不做什么、不能变成什么和现实限制。
4. 定义能够外部核验的完成标准。
5. 为每个完成标准指定证据类型。
6. 记录当前状态、下一步和需要用户决定的事项。

## 更新项目

- 行动发生但证据不足时标记“待验证”。
- 只有完成标准及对应证据成立时标记“已验证”。
- 新事实改变范围或完成标准时，先展示差异并由用户确认。
- 更新前备份原文件；保留关键决策、失败路径和学到的东西。
- 项目状态只使用：`未开始`、`进行中`、`待验证`、`已验证`、`取消`。

## 边界

- 不为所有日常任务制造项目负担。
- 不把 日历 标记或 XP 自动当作项目验收证据。
- 不要求记录与项目无关的私人信息。
- 用户只想讨论项目结构时不创建文件。

# LifeOS 日报与洞察

把一天保存成可靠事实和可复用认识，不用漂亮排版掩盖未知。

## 必读文件

1. [references/daily-report.md](references/daily-report.md)
2. [references/insight.md](references/insight.md)
3. 需要每日签名时读取 [references/quotes.md](references/quotes.md)

## 事实来源

优先级依次为：

1. 用户明确确认
2. 日历 修改后的回读
3. 文件、链接、截图、平台数据或项目记录
4. 清楚标注的用户口述

推断不能冒充事实。缺失信息写“未记录”。

## 工作流

1. 检查目标日期、时区和归档位置。
2. 检查同名日报是否已存在；存在时停止覆盖并报告。
3. 区分行动、结果、证据、卡点和待验证事项。
4. 合并同一目标下的零散小任务。
5. 保留练习原始内容，修正版另列。
6. 只写 XP 最终统计，明细保留在 `xp.md`。
7. 从当天事实与最近 3～7 篇可用日报提炼洞察；历史不足时使用限定语。
8. 写入后回读标题、日期、关键结果和目标路径。

## Markdown 预览与 Obsidian 展示

- 用户询问日报样式、排版或预览效果时，展示 Markdown 结构，并补充：

  > 日报最终使用 Markdown 排版，建议用 Obsidian 等支持 Markdown 阅读的工具查看，效果更完整。如果你有 Obsidian，在你确认仓库位置后，我可以帮你新建 LifeOS 日报文件夹，写入一份示例日报并展示最终效果；不会覆盖已有文件。

- 用户只要求预览时保持只读，不新建文件夹或日报文件。
- 预览也必须读取 `references/daily-report.md` 并复用完整排版顺序；不得省略标题后的“今日签名”和正文结尾的“查看目标进度总览”。
- 预览中的签名从 `references/quotes.md` 选择已核验、积极且适合展示的一句；所有事实区域明确标注为示例，不冒充用户当天记录。
- 用户确认使用 Obsidian 落盘后，先定位并确认目标仓库，再新建专用的 LifeOS 日报文件夹。
- 写入前检查同名文件；存在时停止，不覆盖。写入后回读并提供文件链接或 Markdown 渲染效果。
- 未实际控制 Obsidian 界面时，不声称已经在应用内打开文件；只陈述已创建、已回读或待用户打开的真实状态。

## 写作边界

- 不把日历完成数写成项目结果。
- 不把缺失实践或未知状态写成 0。
- 不做人格、疾病或动机诊断。
- 每日签名必须与当天事实相符；找不到就省略。
- 用户只要求预览时不写文件。
